## Note on completed work, limitations, and improvements

**What's working end to end:** camera registry (add/edit/disable/search/filter,
map, per-camera audit history, health monitoring via a real per-adapter probe, not
a placeholder); two live source types wired up for real (a procedural simulator and
a looped recorded clip) plus a fully functional RTSP adapter and an ONVIF discovery
stub; an analytics ingest API that validates, deduplicates and stores ANPR-style
events; watchlist correlation that generates a real-time alert on match, pushed to
every connected dashboard over WebSocket; vehicle trace across cameras with a map
route and timeline; JWT auth with admin/operator RBAC enforced server-side;
encrypted-at-rest camera credentials; an audit log of sensitive actions; a pytest
suite (25 tests, backend) and CI. Full detail in README.md and ARCHITECTURE.md.

**Limitations, in the interest of being upfront:**
- Watchlist correlation is demonstrated live for vehicle plates (the assignment's
  worked example); person/face watchlist records can be created and managed, but
  live correlation against them needs a face-recognition event source — the
  matching code path is identical, it just isn't exercised by the current demo
  data generator.
- Alerts currently reach connected dashboard sessions only (WebSocket); no
  SMS/push/email fan-out yet.
- Rate limiting is in-process, fine for one instance; a multi-replica deployment
  would need a shared (Redis-backed) limiter.
- No real CCTV footage ships with the repo (none was available under a license
  clear for redistribution) — the recorded-file camera uses a small synthetic clip
  generated by `scripts/generate_sample_video.py`, and this is disclosed in the
  README rather than presented as real footage.

**What I'd do with more time:** move camera health probing for unreachable/slow
RTSP sources into a dedicated worker so a hung native call can be hard-killed;
add a message queue (Kafka/RabbitMQ) in front of ingest so a burst of detections
can't back up the API; partition the detection-events table by time for
retention at scale; add Prometheus/Grafana observability; add Playwright
end-to-end tests for the frontend. All of this is covered in more depth in
SCALABILITY.md and the "Known limitations" section of README.md.
